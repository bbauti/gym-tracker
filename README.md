# Gym Tracker

An offline-first workout tracker for iOS and Android. Log sessions with a rest timer, get progression suggestions and personal records, and keep all data in a local SQLite database.

## Features

- **Workout logging:** per-set weight, reps, and RPE or RIR, a numpad for fast entry, and undo toasts for destructive actions.
- **Timers:** rest timer with local notifications and controls in a sticky session notification, a stopwatch, and an interval timer with a 3-second prep countdown.
- **Routines:** folders, multi-week programs with week-aware rotation, deload days, and import from pasted text, CSV, or JSON.
- **Progression:** next-session suggestions with a stated reason, including stall detection and deload advice.
- **Analytics:** personal records (weight, reps at weight, volume, estimated 1RM), a training heatmap, exercise and body-metric charts, and weekly volume against MEV/MAV/MRV landmarks.
- **Calculators:** plate loading per gym with bar profiles, warm-up ramps, and Wilks/DOTS scores.
- **Data:** full backup and restore, JSON and CSV export, history CSV import, and image sharing of session cards and charts.
- **Exercise search:** SQLite FTS5 across Spanish and English names and aliases.
- **Platform:** optional app lock with biometrics or the device passcode, a "Free workout" quick action from the app icon, Material You tint on Android, and a Spanish/English language setting.

## Tech stack

- Expo SDK 57, React Native 0.86, React 19, TypeScript
- Expo Router (file-based routes, native tabs)
- Drizzle ORM over expo-sqlite (WAL, foreign keys, FTS5)
- React Native Skia (heatmap, muscle map, share cards, celebration effects) and victory-native (charts)
- FlashList, React Native Reanimated, Gesture Handler, Keyboard Controller
- expo-notifications, expo-local-authentication, expo-quick-actions, expo-sharing
- Biome, TypeScript, Bun test

## Architecture

- **Local data layer:** `src/db/client.ts` opens one expo-sqlite database. The Drizzle schema lives in `src/db/schema.ts`, nine SQL migrations run at launch, and a bundled exercise catalog is seeded.
- **Reactive reads:** `src/db/useQuery.ts` re-runs queries on expo-sqlite change events, and only for the focused screen.
- **Domain logic:** progression, PRs, plates, and timers are plain functions in `src/lib/` with no React or Expo imports, each covered by a test file.
- **Routing:** Expo Router routes in `src/app/`. The root layout waits for the database before rendering, and modals are route-based sheets on one root stack.
- **Notifications:** rest and interval alarms are scheduled locally in `src/notifications.ts`. A single module-level listener handles the session notification's action buttons.
- **Native isolation:** biometrics (`src/lock.ts`) and quick actions (`src/quickActions.ts`) are the only files that import their modules. Custom config plugins live in `plugins/`.

## Getting started

Requirements: Node 24 (see `.nvmrc`), Bun, and Xcode (iOS) or Android Studio (Android).

```bash
bun install            # uses the committed bun.lock
npx expo run:ios       # or: npx expo run:android (builds the native projects)
npx expo start         # starts Metro for the installed development build
```

`ios/` and `android/` are generated by Expo prebuild and are not committed. The app uses local config plugins and native modules, so use a development build rather than Expo Go. No environment variables or accounts are required.

## Tests

```bash
bun test src           # 26 test files: database, domain logic, and UI helpers
bun run check          # Biome, TypeScript, and tests
```
